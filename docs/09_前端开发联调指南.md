## 五、API 联调

### 5.1 当前数据流向

```
前端组件 / Store ──(CRUD)──→ features/mindmap/api.ts、features/git/api.ts、utils/api.ts
                                    │
                                    ▼
                       后端 /api/v1（FastAPI，8000）
                                    │
                                    ▼
                     PostgreSQL 主库（maps/nodes/props/git_repos/git_actions）
```

- 页面启动：`loadMaps()` 拉取地图列表（C-1）；进入脑图：`ensureTree()` 拉取整树（C-5）
- 数据变更成功后以服务端返回结果刷新本地缓存；刷新页面不丢数据
- 导入/导出分别调用 `POST /api/v1/maps/import`、`GET /api/v1/maps/export`

### 5.2 后端 API 集成示例

```typescript
// 示例：新增节点（D-1）
async function createNode(mapId: string, payload: { name: string; parent_id?: string }) {
  const response = await fetch(`/api/v1/maps/${mapId}/nodes`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      // 需要鉴权时附加：Authorization: `Bearer ${token}`
    },
    body: JSON.stringify(payload),
  });
  const body = await response.json();   // { code, msg, data }
  if (body.code !== 200) throw new Error(body.msg);
  return body.data;
}
```

### 5.3 API 接口列表（节选）

完整契约见 [15_API接口列表.md](./15_API接口列表.md)，统一前缀 `/api/v1`。

| 接口 | 方法 | 说明 |
|------|------|------|
| `/health`、`/health/postgres`、`/health/neo4j` | GET | 健康检查（Neo4j 可选） |
| `/git/repos` | GET / POST | 仓库列表 / 登记 |
| `/git/repos/{repo_id}` | GET / DELETE | 仓库详情 / 移除 |
| `/git/repos/{repo_id}/commit` | POST | 提交变更 |
| `/git/repos/{repo_id}/pull`、`/push` | POST | 拉取 / 推送 |
| `/fs/dirs`、`/fs/tree` | GET | 目录浏览 / 目录树扫描 |
| `/maps` | GET / POST | 地图列表 / 创建 |
| `/maps/{map_id}` | PUT / DELETE | 更新 / 删除地图 |
| `/maps/{map_id}/tree` | GET / PUT | 整树读取 / 保存 |
| `/maps/import`、`/maps/export` | POST / GET | 导入落库 / 导出 |
| `/maps/{map_id}/nodes` | POST | 新增节点 |
| `/maps/{map_id}/nodes/{node_id}` | PUT / DELETE | 重命名 / 删除节点 |
| `/maps/{map_id}/nodes/{node_id}/props` | POST | 新增属性 |
| `/maps/{map_id}/nodes/{node_id}/props/{prop_id}` | PUT / DELETE | 编辑 / 删除属性 |
| `/maps/{map_id}/nodes/{node_id}/props/{prop_id}/note` | GET / PUT | 读取 / 保存笔记 |

### 5.4 错误处理

```typescript
try {
  const response = await fetch('/api/v1/maps');
  const body = await response.json();
  if (body.code !== 200) {
    throw new Error(body.msg || 'API请求失败');
  }
  return body.data;
} catch (error) {
  message.error('请求失败，请检查网络或后端服务');
}
```

> 后端统一响应为 `{ code, msg, data }`；400/401/403/404/422/500 均按此结构返回。

## 七、代码规范

### 7.1 TypeScript 规范

- 使用 `interface` 定义类型
- 使用 `type` 定义联合类型
- 为所有函数和组件添加类型注解
- 使用 `any` 时需谨慎

### 7.2 组件规范

- 组件名使用 PascalCase
- 文件命名使用 PascalCase
- 使用函数组件 + Hooks
- 避免在组件内部定义函数（使用 `useCallback`）

### 7.3 样式规范

## 十一、2026-11-27 联调补充（FastAPI `app/` 新结构）

> 本章为 v1.2 联调后的最新操作口径，取代前文 Neo4j / `python main.py` 的旧描述。

### 11.1 启动后端（8000）

```bash
cd backend
.venv/bin/python -m alembic upgrade head          # 首次或迁移后
KNOWLEDGE_ROOT=/path/to/knowledge \
  .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- 主数据存储：PostgreSQL（`DATABASE_URL`），`app/main.py` 启动时探测连接，失败降级启动。
- 健康检查：`GET /api/v1/health`、`/health/postgres`、`/health/neo4j`。

### 11.2 启动前端（5173）与跨域

```bash
cd frontend
npm run dev
```

- 前端 API 基础地址由 `VITE_API_BASE_URL` 决定，见 `frontend/.env.development`：
  - 默认 `http://localhost:8000/api/v1`：浏览器直连后端，后端 `CORS_ORIGINS` 必须包含 `http://localhost:5173`；
  - 改为 `/api/v1`：走 `vite.config.ts` 的 `server.proxy`，同源无跨域。
- 后端 `.env` 的 `CORS_ORIGINS` 使用逗号分隔的显式源列表；**不要与 `allow_credentials=true` 搭配 `*`**，否则浏览器会拒绝凭据请求。

### 11.3 数据现状与接入边界

- Git 管理页、导入仓库目录浏览已真实调用后端（`features/git/api.ts`、`utils/api.ts`）。
- **知识地图 / 脑图节点 / 属性 / 笔记（模块 C/D/E/F）已于 2026-11-27 完成服务端接入**，所有数据变更均调用后端并落库 PostgreSQL：
  - API 层：`features/mindmap/api.ts`（C-1～C-8、D-1～D-3、E-1～E-3、F-1/F-2）；
  - 状态层：`store/index.ts` 的 CRUD action 全部改为 async，成功后用服务端返回的整树刷新本地缓存；
  - 页面加载：应用启动 `loadMaps()` 拉取 C-1 列表，进入脑图 `ensureTree()` 拉取 C-5 整树；刷新页面不再丢失数据；
  - 笔记页：按 `mapId/nodeId/propId` 调用 F-1 读取、F-2 保存；
  - 导入：`POST /maps/import` 由后端扫描目录并落库，前端不再本地构造 TreeMap；
  - 导出：`GET /maps/export` 由后端聚合全部地图。
- 本地已移除 `zustand/persist` 与 `SEED_MAPS` 种子数据；`localStorage` 不再承载业务数据，仅保留瞬时 UI 状态（选中、折叠、弹窗等）。
- 属性对象统一携带后端返回的 `prop_id`（`types/index.ts`），用于 E-2/E-3/F-1/F-2 的稳定定位。
