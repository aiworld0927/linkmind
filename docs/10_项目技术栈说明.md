# LinkMind 项目技术栈说明

## 一、技术栈总览

LinkMind 采用前后端分离架构：React SPA 负责知识地图与 Git 管理界面，FastAPI 提供 REST API，PostgreSQL 为事实主库，Neo4j 为派生图索引，知识仓库通过服务端 Git CLI 进行真实版本操作。

> 存储定位：**PostgreSQL（pgvector/pg17）是事实主库**，保存仓库登记、地图/节点/文档模型、审计与向量；**Neo4j 仅作派生图索引**，承载现有笔记/关系/图谱/聚类查询，不承担唯一事实来源职责。

## 二、后端技术栈详解

### 2.1 FastAPI + Pydantic v2

**核心应用**：

- `backend/src/main.py` 创建应用、注册 CORS、异常处理器与全部路由。
- 路由使用 Pydantic 模型接收请求；`GitCommitRequest`、`GitResolveRequest` 使用 `model_validator` 校验跨字段约束。
- 统一响应 `{code, msg, data}`，由 `utils/response.py` 生成。
- 健康检查拆分进程、Neo4j、PostgreSQL 三个端点。
- `lifespan` 初始化 Neo4j 索引与 PostgreSQL 连接；数据库不可用时降级启动。

**关键文件**：

- `backend/src/main.py`
- `backend/src/utils/response.py`
- `backend/src/middleware/exception_handler.py`
- `backend/src/config/settings.py`

### 2.2 PostgreSQL（事实主库）

**核心能力**：

- `backend/migrations/001_init.sql` 建立 10 张表：`knowledge_repository`、`knowledge_map`、`map_node`、`node_property`、`document`、`node_document_link`、`node_link`、`operation_audit`、`git_action`、`document_embedding`。
- 约束：唯一名称/路径、地图标题唯一、文档路径唯一、根/子节点部分唯一索引、禁止自依赖。
- 索引：B-tree、GIN（数组/全文）、BRIN（审计时间）、ivfflat（向量余弦）。
- `database/pg.py` 提供异步引擎、`pool_pre_ping`、请求级会话与异常回滚。

**当前接入范围**：Git 模块使用 `knowledge_repository` 与 `git_action`；其余表为已完成 DDL/ORM 的基线，尚未接入业务读写。

**关键文件**：

- `backend/src/database/pg.py`
- `backend/src/models/db_models.py`
- `backend/migrations/001_init.sql`

### 2.3 Neo4j（派生图索引）

**核心能力**：

- `Note` 节点与 `LINK` 关系承载现有笔记/依赖数据。
- 全文索引、邻域/路径查询、Louvain 社区检测。
- 启动时由 `init_indexes.py` 创建索引。

**边界**：Neo4j 不保存知识仓库登记、审计与向量；与 PostgreSQL 暂无自动同步管道，现有业务路由仍直接读写 Neo4j。

**关键文件**：

- `backend/src/database/neo4j_connection.py`
- `backend/src/database/init_indexes.py`
- `backend/src/models/note.py`、`backend/src/models/link.py`

### 2.4 Git CLI 封装

- `services/git_service.py` 使用 `subprocess.run`，参数列表 + `shell=False` + `timeout=GIT_OPERATION_TIMEOUT`。
- 通过 `-c user.name/-c user.email` 注入提交身份，`GIT_TERMINAL_PROMPT=0` 禁止交互。
- 支持 porcelain v1 状态解析、冲突 stage 内容读取、提交、拉取、推送、解决/继续/放弃合并、历史。
- `services/git_registry_service.py` 负责路径安全、每仓库 `asyncio.Lock`、线程池执行与 `git_action` 审计。

### 2.5 后端分层

```
┌──────────────────────────────────────────────┐
│ routes：HTTP、参数校验、统一响应              │
├──────────────────────────────────────────────┤
│ services：业务规则、事务、Git CLI 编排         │
├──────────────────────────────────────────────┤
│ repositories：SQL / Cypher 数据访问            │
├──────────────────────────────────────────────┤
│ models：Pydantic 模型 + SQLAlchemy ORM         │
├──────────────────────────────────────────────┤
│ database：PostgreSQL 主库 / Neo4j 派生索引     │
└──────────────────────────────────────────────┘
```

约束：路由不写 SQL；仓储只接收 `AsyncSession`；服务层持有 `commit()`；模型与 DDL 同步维护。

## 三、前端技术栈详解

### 3.1 React + TypeScript

- 函数式组件 + Hooks；`App.tsx` 使用 `ConfigProvider`、`ErrorBoundary`、`HashRouter`。
- `tsconfig.json` 开启严格模式与 `exactOptionalPropertyTypes`。
- 全局状态通过 zustand selector 订阅，避免整树重渲染。

**关键文件**：`frontend/src/main.tsx`、`frontend/src/App.tsx`、`frontend/src/types/index.ts`。

### 3.2 Zustand 状态管理

| Store | 位置 | 职责 |
|-------|------|------|
| 画布 store | `frontend/src/store/index.ts` | 数据集/节点/笔记/依赖、视图、操作日志（100 条）、撤销（30 层）、localStorage 持久化（`linkmind_canvas_data`，version 2，写视图 400ms 防抖） |
| Git store | `frontend/src/features/git/store.ts` | 仓库列表/当前仓库、加载与 `busy` 互斥、提交/拉取/推送/冲突/合并操作；数据只来自后端，不持久化 |

### 3.3 AntV X6

- `GraphCanvas.tsx` 注册 React 自定义节点，处理节点拖拽、依赖连线、右键菜单、下钻、缩放与布局。
- `CanvasController` 由画布注册到 store，工具栏调用 `fit/center/zoom/relayout`。

### 3.4 Ant Design

- 页面与表单：`Card/Table/Select/Alert/Empty/Spin/Modal/Drawer/List/Checkbox/Tag/Button`。
- Git 页使用 `Table` 展示变更、`Modal.confirm` 确认移除、`message` 统一反馈。
- 中文语言包 `antd/locale/zh_CN`。

### 3.5 React Router（HashRouter）

| 路由 | 页面 |
|------|------|
| `#/` | `HomePage` |
| `#/map/:datasetId` | `MindMapPage` |
| `#/git` | `GitPage` |
| `#/note` | `NotePage`（查询参数 `title/node/md`） |

### 3.6 Markdown 渲染

- `features/notes/markdown.ts`：先 `escapeHtml` 再渲染白名单语法（h1–h3、列表、引用、代码块、分隔线、行内 code/bold/italic/link），输出 `{html, headings}`。
- `features/notes/MarkdownView.tsx`：大纲、滚动高亮、点击跳转。
- 不解析原始 HTML，`<script>` 等被转义。

### 3.7 Vite + Vitest

- `vite.config.ts`：`@` → `src`，`/api` 代理到 `http://localhost:8000`，端口 5173。
- `vitest.config.ts`：`environment: node`，`include: src/**/*.test.ts`。
- 当前 2 个测试文件、23 个用例：Git 标签映射 9 个、Markdown 渲染 14 个。

## 五、技术选型决策记录

### 5.1 为什么选择 FastAPI 而非 Django/Flask？

| 对比维度 | FastAPI | Django | Flask |
|----------|---------|--------|-------|
| 异步性能 | 高 | 中 | 低 |
| API 文档 | 自动生成 | 需插件 | 需插件 |
| 类型提示 | 原生 | 需插件 | 需插件 |
| 学习曲线 | 低 | 高 | 中 |

**决策**：FastAPI + Pydantic v2 适合本项目的 REST API、参数校验与自动文档需求。

### 5.2 为什么 PostgreSQL 为主库、Neo4j 为派生索引？

| 对比维度 | PostgreSQL | Neo4j |
|----------|------------|-------|
| 事务与约束 | 强约束、外键级联、部分唯一索引 | 灵活但约束弱 |
| 审计与统计 | SQL 聚合、BRIN/GIN | 不擅长 |
| 向量检索 | pgvector + ivfflat | 不承担 |
| 深度关系/路径 | 递归 CTE，复杂 | 原生高效 |
| 聚类 | 需扩展 | Louvain 内置 |

**决策**：知识仓库、地图/节点/文档、审计、向量等事实数据落 PostgreSQL；关系浏览、路径与社区检测保留 Neo4j 作为可重建的派生索引。原「Neo4j 作为主存储」的描述已废弃。

### 5.3 为什么选择 Zustand 而非 Redux？

| 对比维度 | Zustand | Redux |
|----------|---------|-------|
| 代码量 | 轻量 | 需模板与配置 |
| Provider | 不需要 | 必须 |
| TypeScript | 原生友好 | 需额外配置 |
| 学习曲线 | 低 | 高 |

**决策**：画布与 Git 两个独立 store 即可覆盖需求，无需引入 Redux 的样板代码。

### 5.4 为什么选择 X6 而非 D3.js？

| 对比维度 | X6 | D3.js |
|----------|-----|-------|
| 图编辑能力 | 内置拖拽、连线、对齐 | 需自行实现 |
| 节点渲染 | 支持 React 组件 | SVG 操作复杂 |
| 事件系统 | 完善 | 需自行管理 |
| 学习曲线 | 低 | 高 |

**决策**：知识地图需要稳定的节点交互与 React 节点渲染，X6 开箱即用。

### 5.5 为什么使用 HashRouter？

**决策**：生产环境由后端 `StaticFiles` 托管 `frontend/dist`，无 SPA 回退规则；HashRouter 保证 `#/map/:id`、`#/git`、`#/note` 刷新可用。

### 5.6 为什么 Git 操作用服务端 CLI 而非前端库？

**决策**：前端无法可靠访问真实仓库、冲突 stage 与远端凭证；服务端 CLI 与 Git 行为一致，便于用临时裸远端做集成测试。安全上限定 `KNOWLEDGE_ROOT`、`shell=False`、路径校验与超时。
