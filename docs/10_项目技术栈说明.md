# LinkMind 项目技术栈说明

## 一、技术栈总览

LinkMind 采用前后端分离架构：React SPA 负责知识地图与 Git 管理界面，FastAPI 提供 REST API，PostgreSQL 17 为事实主库，知识仓库通过服务端 Git CLI 进行真实版本操作。

> 存储定位：**PostgreSQL 17 是事实主库**，保存 Git 仓库登记、Git 动作审计、知识地图、节点、属性/笔记共 5 张业务表；**Neo4j 5.26 为可选组件**，当前仅用于 `/api/v1/health/neo4j` 连通性检查，不保存主数据，业务接口不依赖。

## 二、后端技术栈详解

### 2.1 FastAPI + Pydantic v2

**核心应用**：

- `backend/app/main.py` 创建应用、注册 CORS、全局异常处理器与 `/api/v1` 路由；启动命令 `uvicorn app.main:app --port 8000`。
- 路由集中在 `backend/app/api/v1/{git,fs,mindmap,health}`，使用 Pydantic 模型接收请求；`GitCommitIn`、`ConflictResolveIn` 使用 `model_validator` 校验跨字段约束。
- 统一响应 `{code, msg, data}`，由 `app/core/response.py` 生成；异常由 `app/core/exceptions.py` 转换为同一结构（参数校验错误返回 422）。
- 健康检查拆分进程、PostgreSQL、Neo4j 三个端点。
- `lifespan` 仅初始化 PostgreSQL 连接；数据库不可用时降级启动。Neo4j 仅在健康检查时惰性连接。
- 所有业务路由通过 `get_current_user` 注入当前用户，默认 `ALLOW_ANONYMOUS=true` 放行；不提供登录接口。

**关键文件**：

- `backend/app/main.py`
- `backend/app/core/response.py`、`backend/app/core/exceptions.py`
- `backend/app/core/config.py`、`backend/app/core/security.py`
- `backend/app/api/v1/router.py`

### 2.2 PostgreSQL（事实主库）

**核心能力**：

- Alembic 基线 `backend/alembic/versions/0001_baseline.py` 建立 5 张业务表：`git_repos`、`git_actions`、`maps`、`nodes`、`props`；`backend/migrations/001_init.sql` 为等价的可重复执行 SQL。
- 约束：仓库名/路径唯一、地图标题唯一、节点同级不重名（部分唯一索引）、外键级联删除、地图 `repo_id` 删除仓库后置空。
- 索引：B-tree（仓库审计、地图节点、属性查询）与部分唯一 B-tree；当前未使用 GIN/BRIN/ivfflat。
- `app/db/session.py` 提供异步引擎、`pool_pre_ping`、请求级会话与异常回滚。
- 详细字段与 DDL 见 [19_数据库设计.md](./19_数据库设计.md)。

**当前接入范围**：5 张表均已接入业务读写——地图/节点/属性/笔记由 mindmap 模块落库，仓库登记与动作审计由 git 模块落库；Git 运行时状态（分支、领先落后、变更、冲突）实时通过 `git` CLI 计算，不落库。

**关键文件**：

- `backend/app/db/session.py`、`backend/app/db/base.py`
- `backend/app/api/v1/git/models.py`、`backend/app/api/v1/mindmap/models.py`
- `backend/alembic/versions/0001_baseline.py`、`backend/migrations/001_init.sql`

### 2.3 Neo4j（可选，仅健康检查）

**边界**：

- 当前 `backend/app` 不包含笔记/关系/图谱业务路由，也没有 Neo4j 索引初始化。
- 仅在 `GET /api/v1/health/neo4j` 中惰性创建 driver 并校验连通性；主数据不写入 Neo4j。
- compose 中的 `neo4j` 服务为可选组件，不影响 PostgreSQL 主链路。

**关键文件**：

- `backend/app/api/v1/health/router.py`
- `backend/app/core/config.py`（`NEO4J_URI/USER/PASSWORD`）

### 2.4 Git CLI 封装

- `app/api/v1/git/service.py` 使用 `subprocess.run`，参数列表 + `shell=False` + `timeout=GIT_OPERATION_TIMEOUT`。
- 通过 `-c user.name/-c user.email` 注入提交身份，`GIT_TERMINAL_PROMPT=0` 禁止交互。
- 支持 porcelain v1 状态解析、冲突 stage 内容读取、提交、拉取、推送、解决/继续/放弃合并、历史。
- `app/api/v1/git/service.py` 中的仓库服务负责路径安全、每仓库 `asyncio.Lock`、线程池执行与 `git_actions` 审计；`repository.py` 负责 SQL 访问。

### 2.5 后端分层

```
┌──────────────────────────────────────────────┐
│ api/v1 routers：HTTP、参数校验、统一响应      │
├──────────────────────────────────────────────┤
│ services：业务规则、事务、Git CLI 编排         │
├──────────────────────────────────────────────┤
│ repositories：SQL 数据访问（AsyncSession）     │
├──────────────────────────────────────────────┤
│ models：模块内 SQLAlchemy ORM + Pydantic schema│
├──────────────────────────────────────────────┤
│ db / core：PostgreSQL 会话、配置、异常、鉴权   │
└──────────────────────────────────────────────┘
```

约束：路由不写 SQL；仓储只接收 `AsyncSession`；服务层持有 `commit()`；模型与 Alembic 迁移同步维护。

## 三、前端技术栈详解

### 3.1 React + TypeScript

- 函数式组件 + Hooks；`App.tsx` 使用 `ConfigProvider`、`HashRouter`、路由表与全局弹窗容器。
- `tsconfig.json` 开启严格模式与 `exactOptionalPropertyTypes`。
- 全局状态通过 zustand selector 订阅，避免整树重渲染。

**关键文件**：`frontend/src/main.tsx`、`frontend/src/App.tsx`、`frontend/src/types/index.ts`。

### 3.2 Zustand 状态管理

| Store | 位置 | 职责 |
|-------|------|------|
| 画布 store | `frontend/src/store/index.ts` | 地图/节点/属性/笔记的加载与 CRUD、视图、操作日志（200 条）、折叠状态、选中节点；所有写操作调用服务端 API，数据以 PostgreSQL 为准，不做 localStorage 持久化 |
| Git store | `frontend/src/features/git/store.ts` | 仓库列表/当前仓库、加载与 `busy` 互斥、提交/拉取/推送/冲突/合并操作；数据只来自后端，不持久化 |

### 3.3 自研 SVG 画布

- `features/mindmap/MindCanvas.tsx` 使用 SVG 递归自动布局，支持拖拽平移、滚轮缩放、搜索高亮、右键菜单与折叠。
- 布局与缩放算法集中在 `utils/layout.ts`（`build/fitView` 及 `FIT_*`、`VIEW_*` 常量）。
- 节点交互通过 zustand store 触发，右侧属性抽屉 `SideDrawer.tsx`、弹窗 `Modals.tsx`、日志 `LogDrawer.tsx`、右键菜单 `CtxMenu.tsx` 分别承载对应交互。
- 项目未引入 AntV X6/D3 等图库。

### 3.4 Ant Design

- 页面与表单：`Card/Table/Select/Alert/Empty/Spin/Modal/Drawer/List/Checkbox/Tag/Button`。
- Git 页使用 `Table` 展示变更、`Modal.confirm` 确认移除、`message` 统一反馈。
- 中文语言包通过 `ConfigProvider` 配置（`App.tsx`）。

### 3.5 React Router（HashRouter）

| 路由 | 页面 |
|------|------|
| `#/` | `HomePage` |
| `#/map/:mapId` | `MindMapPage` |
| `#/git` | `GitPage` |
| `#/note` | `NotePage`（查询参数 `title/node/md`） |

### 3.6 Markdown 渲染

- `features/notes/markdown.ts`：先 `escapeHtml` 再渲染白名单语法（h1–h3、列表、引用、代码块、分隔线、行内 code/bold/italic/link），输出 `{html, headings}`。
- `features/notes/MarkdownView.tsx`：大纲、滚动高亮、点击跳转。
- 编辑态使用 `VditorEditor.tsx`（Vditor 3.10，资源本地化）。
- 不解析原始 HTML，`<script>` 等被转义。

### 3.7 前端数据层

| 文件 | 职责 |
|------|------|
| `frontend/src/utils/http.ts` | 统一 `request()`：`VITE_API_BASE_URL` 缺省 `/api/v1`，解析 `{code,msg,data}`，非 200 抛 `ApiError` |
| `frontend/src/features/mindmap/api.ts` | 地图 C-1～C-8、节点 D-1～D-3、属性 E-1～E-3、笔记 F-1～F-2 客户端 |
| `frontend/src/features/git/api.ts` | Git A-1～A-12 与 `/fs/dirs` 客户端 |
| `frontend/src/store/index.ts` | 调用上述 API 完成地图/节点/属性/笔记的读取与落库 |

### 3.8 Vite + Vitest

- `vite.config.ts`：`@` → `src`，`/api` 代理到 `http://localhost:8000`，开发端口 5173。
- `vitest.config.ts`：`include: src/**/*.test.ts`。
- 当前 2 个测试文件、23 个用例（Git 标签映射 9 个、Markdown 渲染 14 个），全部通过。

## 五、技术选型决策记录

### 5.1 为什么选择 FastAPI 而非 Django/Flask？

| 对比维度 | FastAPI | Django | Flask |
|----------|---------|--------|-------|
| 异步性能 | 高 | 中 | 低 |
| API 文档 | 自动生成 | 需插件 | 需插件 |
| 类型提示 | 原生 | 需插件 | 需插件 |
| 学习曲线 | 低 | 高 | 中 |

**决策**：FastAPI + Pydantic v2 适合本项目的 REST API、参数校验与自动文档需求。

### 5.2 为什么 PostgreSQL 为主库、Neo4j 可选？

| 对比维度 | PostgreSQL | Neo4j |
|----------|------------|-------|
| 事务与约束 | 强约束、外键级联、部分唯一索引 | 灵活但约束弱 |
| 审计与统计 | SQL 聚合、B-tree 索引 | 不擅长 |
| 向量检索 | 当前未启用（未来可扩展） | 不承担 |
| 深度关系/路径 | 递归 CTE，复杂 | 原生高效 |
| 聚类 | 需扩展 | Louvain 内置 |

**决策**：Git 仓库登记/审计、地图/节点/属性/笔记等事实数据全部落 PostgreSQL；当前版本不使用 Neo4j 承载业务，仅保留可选容器与健康检查。原「Neo4j 作为主存储」的描述已废弃；历史 10 表方案（含文档、向量、节点关系）未落地，见 [19_数据库设计.md](./19_数据库设计.md)。

### 5.3 为什么选择 Zustand 而非 Redux？

| 对比维度 | Zustand | Redux |
|----------|---------|-------|
| 代码量 | 轻量 | 需模板与配置 |
| Provider | 不需要 | 必须 |
| TypeScript | 原生友好 | 需额外配置 |
| 学习曲线 | 低 | 高 |

**决策**：画布与 Git 两个独立 store 即可覆盖需求，无需引入 Redux 的样板代码。

### 5.4 为什么使用自研 SVG 画布而非 X6/D3？

| 对比维度 | 自研 SVG | X6 / D3 |
|----------|----------|---------|
| 依赖体积 | 无额外图库 | 引入完整图引擎 |
| 交互贴合度 | 与原型一致，按需实现拖拽/缩放/折叠 | 需适配默认行为 |
| 布局算法 | `utils/layout.ts` 完全可控 | 需二次封装 |
| 学习/维护成本 | 代码量小、可读 | API 面较广 |

**决策**：当前脑图是树形层级 + 自动布局的固定场景，自研 SVG 递归布局（`features/mindmap/MindCanvas.tsx`）已覆盖拖拽平移、滚轮缩放、搜索高亮、右键菜单与折叠，无需引入 X6/D3。

### 5.5 为什么使用 HashRouter？

**决策**：生产环境由 `linkmind-web`（Nginx）托管 `frontend/dist`，`nginx.conf` 已配置 `try_files $uri $uri/ /index.html` 兜底；仍使用 HashRouter，使 `#/map/:mapId`、`#/git`、`#/note` 在任意静态托管方式下都能直接刷新，不依赖服务端路由回退规则。

### 5.6 为什么 Git 操作用服务端 CLI 而非前端库？

**决策**：前端无法可靠访问真实仓库、冲突 stage 与远端凭证；服务端 CLI 与 Git 行为一致，便于用临时裸远端做集成测试。安全上限定 `KNOWLEDGE_ROOT`、`shell=False`、路径校验与超时。
