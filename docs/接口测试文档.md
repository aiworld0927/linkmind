

验证 `/docs`：


### 2.4 获取 Token

本项目按 [18_后端工程结构设计.md](./18_后端工程结构设计.md) 决策 3 **不提供登录接口**，Token 由服务端 `SECRET_KEY` 本地签发（与实例 B 使用同一 `.env`）：

```bash
cd backend
```

> `TEST_PASSWORD` 为预留项——由于契约内无登录接口，当前不参与签发，已在脚本注释中标注。

## 三、测试脚本说明（scripts/api-test.sh）

| 能力 | 实现 |
|------|------|
| 严格模式 | `set -euo pipefail`；断言失败不中断，统一计数 |
| 依赖 | `bash` + `curl` + `jq`；**jq 缺失时自动回退到 python 等价 JSON 解析**（本机无 jq，已通过回退分支实测） |
| 环境变量 | `BASE_URL`、`AUTH_BASE_URL`、`TOKEN`、`TEST_USERNAME`、`TEST_PASSWORD`、`KNOWLEDGE_ROOT`、`KB_SUBDIR`、`GIT_SUBDIR` |
| 状态码断言 | `expect_status <名称> <期望HTTP>` |
| 业务码断言 | `expect_code <名称> <期望 body.code>` |
| 字段断言 | `expect_eq` / `expect_ge` / `expect_nonempty`（点号路径取值，如 `.data.items.0.id`） |
| 契约校验 | 调用 `/openapi.json` 校验 25 条接口路径存在性 |
| 动态变量 | `REPO_ID` / `MAP_ID` / `NODE_A` / `NODE_B` / `PROP_A` / `ROOT_PROP` 均从响应中提取 |
| 汇总 | 末尾输出 总数 / 通过 / 失败 + 失败明细，失败时退出码 1 |

执行顺序依赖（脚本内已按此顺序编排）：

```
C-2 创建地图 → C-3 更新 → C-6 建树 → D-1 建节点 → D-2 重命名 → E-1 建属性 → F-1/F-2 笔记 → E-3/D-3/C-4 删除
A-3 登记仓库 → A-5 提交 → A-6/A-7/A-8/A-9/A-10 动作 → A-11/A-12 查询 → A-4 移除
```
