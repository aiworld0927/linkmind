## 五、遗留问题与建议

### 5.1 知识地图 / 节点 / 属性 / 笔记前端未接后端（最高优先级，待确认）

- 现状：首页、脑图、笔记页均读写 Zustand 内存（种子数据见 [config/maps.ts](file:///coding/linkmind/frontend/src/config/maps.ts)），刷新即丢；后端 C/D/E/F 共 16 个操作已实现并通过联调。
- 影响：产品“持久化知识地图”的核心价值无法端到端体现。
- 建议实施路径（需产品确认后执行）：
  1. 新增 `features/mindmap/api.ts`：`listMaps/getTree/createMap/updateMap/deleteMap/createNode/renameNode/deleteNode/createProp/updateProp/deleteProp/getNote/updateNote`；
  2. 路由进入时拉取 `GET /maps/{id}/tree`，store 作为缓存并保留乐观更新；
  3. 写操作二选一：画布批量变更走 `PUT /maps/{id}/tree`（C-6），抽屉/右键细粒度操作走 D/E/F；
  4. 属性对象必须回填 `prop_id`；笔记页改为按 `mapId/nodeId/propId` 拉取 F-1，保存走 F-2；
  5. 同步处理 C-8 导出标识（`linkmind`）与时间展示格式。

### 5.2 鉴权链路不完整（待确认）

- 后端按设计不提供登录接口，Token 只能由服务端 `SECRET_KEY` 签发；前端没有登录页与 Token 注入逻辑。
- 当前 `ALLOW_ANONYMOUS=true`，联调可匿名通过；生产若切换 `false`，前端 Git 页会 401。
- 建议：明确生产鉴权方案（网关统一注入 / 新增登录接口），再补前端 Token 存储与自动附加。

### 5.3 Git 远端场景未覆盖

- 本次未配置真实远端，仅验证 `pull/push` 无上游分支返回 400；冲突解决仅覆盖非冲突/缺 content 分支。
- 建议在预发环境用真实远端执行一次“拉取冲突 → 解决 → 继续合并 / 中止合并”全流程。

### 5.4 UI 自动化 E2E 缺失

- 本次前端验证为类型检查、单测、构建、开发服务与代理实测；未引入 Playwright/Cypress 浏览器级回归。
- 建议补充 Git 页与地图页的关键路径 UI 用例。

### 5.5 其他

- 构建产物 `index-*.js` 约 957KB（gzip 292KB），建议按路由/编辑器（Vditor）做动态分包。
- Git 历史时间当前直接展示原始 ISO 字符串，可用已有的 `dayjs` 格式化（非阻塞）。
