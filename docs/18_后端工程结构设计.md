## 一、已确认决策（4 项）

| # | 决策 | 结论 |
|---|------|------|
| 1 | 工程落位 | **原地重构**：在现有 `backend/` 下新建 `app/` 分层结构，git/fs 逻辑从旧 `src/` 迁入，验证通过后切换启动入口并下线旧 `src/`。前端契约（路径/响应格式）不变 |
| 2 | 实现范围 | **两阶段全做**：阶段1 = Git(12) + FS(3)；阶段2 = 知识地图 C/D/E/F(16)。按评审建议默认方案：**D/E/F 细粒度为常规通道、C-6 整树保存仅作批量同步、prop_id 为主键**（Q9/Q12 按此默认先行，后续正式答复若有出入再调整） |
| 3 | 鉴权 | **JWT + 匿名开关**：实现 `core/security.py`（OAuth2PasswordBearer + JWT + current_user 依赖），`ALLOW_ANONYMOUS=true`（默认）时放行；**不新增登录接口**（文档外） |
| 4 | 旧接口处置 | **health 保留**（部署验收依赖连通性检查），其余 6 组（note/link/graph/expand/search/cluster/markdown_import）留在旧代码不迁移，新结构不实现 |

**硬性约束**：不实现文档 31 项之外的任何业务接口（含 import-json/后端导出/登录）；统一响应 `{code, msg, data}` 且 `code===200` 为成功；全链路 async。

## 二、目录结构

```
backend/
  app/
    main.py                    # FastAPI 实例、CORS、路由注册、全局异常处理、lifespan（engine 建连/断开）
    core/
      config.py                # Settings(pydantic-settings)：DATABASE_URL、SECRET_KEY、CORS_ORIGINS、KNOWLEDGE_ROOT、ALLOW_ANONYMOUS、JWT_EXPIRE_MINUTES
      security.py              # JWT 编解码、OAuth2PasswordScheme、get_current_user 依赖（ALLOW_ANONYMOUS=true 时返回匿名用户）
      exceptions.py            # AppException(code, msg, http_status) + register_exception_handlers：RequestValidationError→{code:422}、HTTPException 透传、AppException→对应状态码、兜底 500
      constants.py             # ErrorCode(Enum)：OK=200/BAD_REQUEST=400/NOT_FOUND=404/VALIDATION_ERROR=422/INTERNAL_ERROR=500 + git/fs/mindmap 业务错误码
      deps.py                  # get_db(yield AsyncSession)、分页依赖(page≥1, page_size 1~100 默认 20)
      logging.py               # logging 统一配置
      pagination.py            # Page[T] 泛型 {total:int, items:list[T]}
    db/
      base.py                  # DeclarativeBase + naming_convention + TimestampMixin(created_at/updated_at timestamptz) + uuid 主键默认（uuid4）
      session.py               # create_async_engine(asyncpg) + async_sessionmaker(expire_on_commit=False)
    api/v1/
      router.py                # 汇总 include_router，prefix=/api/v1
      git/                     # A 模块 12 端点：/git/repos 系列
        {router,schemas,service,repository,models}.py
      fs/                      # B-1 /fs/dirs、B-2 /fs/tree、F-3 /docs/content（同文件系统域；无 ORM，KNOWLEDGE_ROOT 约束与路径遍历拦截在 service）
        {router,schemas,service}.py
      mindmap/                 # C+D+E+F 聚合域（同一聚合根：地图树）
        models.py              # MapModel/NodeModel/PropModel
        repository.py          # 全部数据访问
        service.py             # 业务逻辑（可拆 service/maps.py、nodes.py、props.py、notes.py）
        schemas/{maps,nodes,props,notes}.py
        routers/{maps,nodes,props,notes}.py
    db/seed.py                 # 可选种子脚本
  alembic/
    env.py                     # async 模式；versions/ 迁移
  tests/                       # pytest + pytest-asyncio + httpx.AsyncClient（按模块）
  .env.example                 # DATABASE_URL/SECRET_KEY/CORS_ORIGINS/KNOWLEDGE_ROOT/ALLOW_ANONYMOUS/JWT_EXPIRE_MINUTES
  pyproject.toml  README.md
```

**分层调用链**：router（校验/依赖/response_model）→ service（业务规则，全 async）→ repository（AsyncSession + SQLAlchemy 2.0 select/insert）→ models（Mapped[] 注解）。schemas 用 `ConfigDict(from_attributes=True)` 与 ORM 解耦。

**响应包装**：`ApiResponse[T] = {code:int, msg:str, data:T|None}`，router 统一包装返回；异常路径返回 `{code, msg, data: None}`。

## 四、数据库表设计（PostgreSQL 17）

- `git_repos`：id uuid PK、name varchar(120)、fs_path varchar（相对 KNOWLEDGE_ROOT）、remote_url varchar nullable、timestamptz 时间戳
- `git_actions`：id uuid PK、repo_id FK→git_repos、ts timestamptz、action varchar、message text、files jsonb、ok boolean
- `maps`：id uuid PK、title varchar(30) unique、desc varchar(80)、repo_id FK→git_repos nullable、timestamptz
- `nodes`：id uuid PK、map_id FK→maps、parent_id self-FK nullable（null=一级）、name varchar(30)、sort_order int、timestamptz
- `props`：id uuid PK、map_id FK→maps、node_id FK→nodes nullable（null=地图级，对应前端 ROOT）、label varchar(30)、note_content text、note_tags jsonb、note_remark varchar(60)、doc boolean、doc_path varchar nullable、timestamptz
- git 运行时状态（branch/ahead/behind/merging/files/conflicts）实时计算不落库；Alembic 基线迁移一份覆盖全部 5 表

## 五、迁移策略（原地重构）

1. 新建 `backend/app/` 全套；git 模块业务逻辑从旧 `src/services/git_service.py`、`src/services/git_registry_service.py` 迁入并适配分层（subprocess 用 shell=False + 超时 + 单仓库串行 + 审计写 git_actions，保持安全约束）
2. fs 模块从旧 `src/routes/fs.py` 逻辑迁入，保留 KNOWLEDGE_ROOT 约束与路径遍历拦截
3. health 端点在新结构实现（保留 /api/v1/health、/health/neo4j、/health/postgres 语义）
4. 验证：uvicorn 启动 → /docs 可访问 → 前端 5173 全功能回归 → 切换 Dockerfile/启动命令 → 下线旧 `src/`（保留文件暂不物理删除，入口切走即可）
5. 每完成一个模块输出「接口实现清单」：路径 → 文件位置 → schema；全部完成后输出「实现对照表」（31 项 100% 覆盖核对）
