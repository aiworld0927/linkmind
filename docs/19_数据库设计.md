## 一、总体设计

| 项目 | 说明 |
|------|------|
| 数据库 | PostgreSQL 17（Docker 镜像 `pgvector/pgvector:pg17`） |
| 主库定位 | **事实主库**，保存仓库登记、地图、节点、属性/笔记、Git 审计 |
| Neo4j | 仅保留健康检查连通性验证，业务接口不依赖，不保存主数据 |
| ORM | SQLAlchemy 2.0 async（`asyncpg`），`Mapped[]` 声明式模型 |
| 迁移 | Alembic（`0001_baseline`，async env） |
| 主键 | 业务表统一 `uuid`，默认 `gen_random_uuid()`（PG 13+ 内置） |
| 时间 | 统一 `timestamptz`；`created_at` / `updated_at` 默认 `now()` |
| 命名 | `snake_case`；索引 `ix_`、唯一索引 `uq_`、主键 `pk_`、外键 `fk_`、约束 `ck_` |
| 删除策略 | 地图/节点/属性采用数据库级 `ON DELETE CASCADE`，仓库删除后地图 `repo_id` 置空 |
| 字符集 | UTF-8（数据库默认） |

当前共 **5 张业务表**：

```
git_repos 1 ── n git_actions
git_repos 1 ── n maps            （repo_id 可空，ON DELETE SET NULL）
maps      1 ── n nodes           （ON DELETE CASCADE）
nodes     1 ── n nodes           （parent_id 自引用，ON DELETE CASCADE）
maps      1 ── n props           （ON DELETE CASCADE）
nodes     1 ── n props           （node_id 可空；NULL = 地图级属性）
```

```
┌────────────┐        ┌──────────────┐
│ git_repos  │1      n│ git_actions  │
└─────┬──────┘        └──────────────┘
      │1
      │  repo_id (SET NULL)
      │n
┌─────▼──────┐        ┌──────────────┐
│   maps     │1      n│    nodes     │
└─────┬──────┘        └──────┬───────┘
      │1                     │ parent_id (self)
      │                      │
      │n                     │n
┌─────▼──────────────────────▼───────┐
│               props                │
│  node_id IS NULL → 地图级(前端ROOT) │
└────────────────────────────────────┘
```

## 二、表结构明细

### 2.1 `git_repos` — Git 仓库登记

真实知识仓库登记表；`fs_path` 为相对 `KNOWLEDGE_ROOT` 的目录，服务端 Git 操作限定在此目录内。

| 字段 | 类型 | 空 | 默认 | 说明 |
|------|------|----|------|------|
| `id` | uuid | 否 | `gen_random_uuid()` | 主键 |
| `name` | varchar(120) | 否 | — | 仓库显示名，唯一 |
| `fs_path` | varchar(1024) | 否 | — | 相对 `KNOWLEDGE_ROOT` 的路径，唯一 |
| `remote_url` | varchar(1024) | 是 | NULL | 远端地址（可空） |
| `created_at` | timestamptz | 否 | `now()` | 创建时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间（ORM `onupdate`） |

约束/索引：

- `pk_git_repos`：主键；
- `uq_git_repos_name`：仓库名唯一；
- `uq_git_repos_fs_path`：目录唯一。

> Git 运行时状态（branch / ahead / behind / merging / files / conflicts）**不落库**，每次读取实时执行 `git` 命令计算。

### 2.2 `git_actions` — Git 动作审计

不可变审计记录，每次拉取/提交/推送/冲突处理等动作写入一条。

| 字段 | 类型 | 空 | 默认 | 说明 |
|------|------|----|------|------|
| `id` | uuid | 否 | `gen_random_uuid()` | 主键 |
| `repo_id` | uuid | 否 | — | → `git_repos.id` |
| `ts` | timestamptz | 否 | `now()` | 动作时间 |
| `action` | varchar(40) | 否 | — | 动作类型（commit/pull/push/...） |
| `message` | text | 否 | — | 动作说明/提交信息 |
| `files` | jsonb | 否 | `'[]'::jsonb` | 涉及文件数组 |
| `ok` | boolean | 否 | `true` | 是否成功 |

约束/索引：

- `fk_git_actions_repo_id_git_repos`：`ON DELETE CASCADE`；
- `ix_git_actions_repo_id`：按仓库查询审计。

### 2.3 `maps` — 知识地图

| 字段 | 类型 | 空 | 默认 | 说明 |
|------|------|----|------|------|
| `id` | uuid | 否 | `gen_random_uuid()` | 主键 |
| `title` | varchar(30) | 否 | — | 地图标题，全局唯一 |
| `desc` | varchar(80) | 否 | `''` | 地图描述 |
| `repo_id` | uuid | 是 | NULL | → `git_repos.id`，仓库删除后置空 |
| `created_at` | timestamptz | 否 | `now()` | 创建时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间 |

约束/索引：

- `uq_maps_title`：地图标题唯一（接口层同时做重名校验）；
- `fk_maps_repo_id_git_repos`：`ON DELETE SET NULL`。

> `maps` 行即前端脑图的“根节点（ROOT）”；ROOT 不单独建 `nodes` 行。

### 2.4 `nodes` — 地图节点

| 字段 | 类型 | 空 | 默认 | 说明 |
|------|------|----|------|------|
| `id` | uuid | 否 | `gen_random_uuid()` | 主键 |
| `map_id` | uuid | 否 | — | → `maps.id` |
| `parent_id` | uuid | 是 | NULL | 自引用；NULL = 一级节点 |
| `name` | varchar(30) | 否 | — | 节点名称 |
| `sort_order` | integer | 否 | `0` | 同级排序 |
| `created_at` | timestamptz | 否 | `now()` | 创建时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间 |

约束/索引：

- `fk_nodes_map_id_maps`：`ON DELETE CASCADE`；
- `fk_nodes_parent_id_nodes`：`ON DELETE CASCADE`；
- `ix_nodes_map (map_id)`：按地图取节点；
- `ux_nodes_root_name (map_id, name) WHERE parent_id IS NULL`：一级节点同级不重名；
- `ux_nodes_child_name (parent_id, name) WHERE parent_id IS NOT NULL`：子节点同级不重名。

> 层级通过 `parent_id` 递归构建，不存储 `path`/`depth`；响应中的 `path` 由服务层递归拼接。

### 2.5 `props` — 节点属性 / 笔记

| 字段 | 类型 | 空 | 默认 | 说明 |
|------|------|----|------|------|
| `id` | uuid | 否 | `gen_random_uuid()` | 主键，接口返回为 `prop_id` |
| `map_id` | uuid | 否 | — | → `maps.id` |
| `node_id` | uuid | 是 | NULL | → `nodes.id`；NULL = 地图级（前端 ROOT） |
| `label` | varchar(30) | 否 | — | 属性名 |
| `note_content` | text | 否 | `''` | 笔记正文（Markdown） |
| `note_tags` | jsonb | 否 | `'[]'::jsonb` | 标签数组 |
| `note_remark` | varchar(60) | 否 | `''` | 备注 |
| `doc` | boolean | 否 | `false` | 是否关联文档属性 |
| `doc_path` | varchar(1024) | 是 | NULL | 文档相对路径 |
| `created_at` | timestamptz | 否 | `now()` | 创建时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间 |

约束/索引：

- `fk_props_map_id_maps`、`fk_props_node_id_nodes`：均 `ON DELETE CASCADE`；
- `ix_props_map_node (map_id, node_id)`：按地图/节点取属性。

> 属性接口返回 `prop_id` 即本表 `id`；前端编辑/删除属性、读取/保存笔记均以 `prop_id` 定位。

## 四、初始化与迁移

### 4.1 推荐方式：Alembic

```bash
cd backend
.venv/bin/python -m alembic upgrade head      # 建表/升级
.venv/bin/python -m alembic current           # 查看当前版本
.venv/bin/python -m alembic check             # 校验模型与库结构是否漂移
```

当前基线：`0001_baseline`（`down_revision = None`）。

### 4.2 空库快速初始化：SQL

`backend/migrations/001_init.sql` 与 `0001_baseline` 等价，幂等可重复执行：

```bash
psql "postgresql://linkmind:linkmind@localhost:5432/linkmind" \
  -f backend/migrations/001_init.sql
```

脚本末尾会创建 `alembic_version` 并写入 `0001_baseline`，使 SQL 初始化后的库与 Alembic 基线状态一致：后续 `alembic upgrade head` 为空操作，`alembic check` 可直接比对模型漂移。

Docker Compose 会把该文件挂载到 `/docker-entrypoint-initdb.d/001_init.sql`，**仅在数据卷为空时执行一次**；已有数据卷请使用 Alembic。

### 4.3 种子数据（可选）

```bash
cd backend
.venv/bin/python -m app.db.seed
```

仅当 `maps` 为空时插入 1 张地图、2 个节点、2 个属性。

### 4.4 变更流程

1. 修改 `app/api/v1/**/models.py`；
2. 生成迁移：`alembic revision --autogenerate -m "..."`；
3. 人工复核迁移（命名、索引、`ON DELETE`）；
4. 同步更新本文件与 `001_init.sql`（如涉及空库基线）；
5. `alembic upgrade head` + `alembic check` + 后端测试。

## 六、索引与容量建议

| 索引 | 类型 | 用途 |
|------|------|------|
| `ix_git_actions_repo_id` | B-tree | 按仓库查审计 |
| `ix_nodes_map` | B-tree | 按地图取节点 |
| `ux_nodes_root_name` / `ux_nodes_child_name` | 部分唯一 B-tree | 同级节点去重 |
| `ix_props_map_node` | B-tree | 按地图/节点取属性 |

- 当前数据量级为单机知识库，以上索引足够；`nodes.parent_id` 自引用查询为递归内存构建，未额外建索引。
- 若后续出现文档全文检索/向量检索需求，应通过**新增 Alembic 迁移**添加 `document`、`document_embedding` 等表；历史设计中的 10 表方案并未落地，不能直接当作现状。
- 备份建议：`pg_dump -Fc` 逻辑备份 + 定期恢复演练；详见 [05_运维手册.md](./05_运维手册.md)。

## 七、一致性与校验

```sql
-- 表清单（应为 5 张业务表 + alembic_version）
SELECT tablename FROM pg_tables WHERE schemaname = 'public' ORDER BY 1;

-- 索引清单
SELECT indexname, tablename FROM pg_indexes WHERE schemaname = 'public' ORDER BY 1;

-- 孤儿数据检查（应为 0）
SELECT count(*) FROM nodes n LEFT JOIN maps m ON m.id = n.map_id WHERE m.id IS NULL;
SELECT count(*) FROM props p LEFT JOIN maps m ON m.id = p.map_id WHERE m.id IS NULL;
SELECT count(*) FROM props p LEFT JOIN nodes n ON n.id = p.node_id
 WHERE p.node_id IS NOT NULL AND n.id IS NULL;
```

`alembic check` 通过、后端 `pytest` 通过、接口联调 197/197 通过，视为数据库交付达标。

> 若表清单中出现历史 10 表（`knowledge_map`、`map_node` 等），说明该数据卷来自旧版本；应用不会读写这些表，`alembic check` 会报告“待删除表”。确认已备份后可人工清理，详见 [02_部署手册.md](./02_部署手册.md) Q9。

## 八、历史设计说明（重要）

早期文档（`10/12/13/14`）曾设计 10 张表：`knowledge_repository`、`knowledge_map`、`map_node`、`node_property`、`document`、`node_document_link`、`node_link`、`operation_audit`、`git_action`、`document_embedding`。

**该方案未落地**。当前实际实现为本文 5 张表：`git_repos`、`git_actions`、`maps`、`nodes`、`props`。差异原因：

- 前端脑图模型天然是“地图 → 节点 → 属性”，采用 `maps/nodes/props` 更直接；
- Git 审计与仓库登记独立，采用 `git_repos/git_actions`；
- 文档、依赖关系、操作审计、向量检索尚未进入当前版本范围，待需求确认后再通过 Alembic 增量迁移引入。

如数据库中残留旧表，请在备份后人工确认并清理；应用不会读写这些表。
