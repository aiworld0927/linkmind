> **旧架构说明（2026-11-27）**：本文部分章节保留了早期设计表述。当前实际架构为：后端 `backend/app`（FastAPI，`uvicorn app.main:app --port 8000`，接口前缀 `/api/v1`）、PostgreSQL 17 主存储（Alembic `0001_baseline`，5 张业务表）、React + Vite 前端。文中 `backend/src`、`python main.py`、Neo4j 主存储、`/api` 等均属旧口径，下文已按当前实现标注或修正；旧前端组件（`GraphCanvas`、`NoteList`、`NodeModal` 等）的源码链接已失效，仅作历史参考；产品方法论内容保持不变。

```typescript
// 循环依赖检测
checkCircleDepend: (nodeList, newDependIds, selfId) => {
  const visited = new Set();
  const stack = [...newDependIds];
  
  while (stack.length > 0) {
    const currentId = stack.pop();
    if (!currentId) continue;
    if (currentId === selfId) return true;
    if (visited.has(currentId)) continue;
    visited.add(currentId);
    
    const currentNode = nodeList.find(n => n.id === currentId);
    if (currentNode) {
      stack.push(...currentNode.dependencies);
    }
  }
  return false;
}
```

**核心代码示例**：

```typescript
// 层级下钻
drillDown: (targetNodeId) => {
  const node = state.currentNodes.find(n => n.id === targetNodeId);
  if (!node) return;
  
  // 保存当前层级到历史
  const historyEntry = {
    levelId: state.currentLevelId,
    nodes: state.currentNodes.map(n => ({ ...n })),
    breadcrumbs: [...state.breadcrumbs],
  };
  
  // 将笔记转换为子节点
  const childNodes = node.children.map(child => convertListItemToNodeItem(child));
  
  // 更新状态
  set({
    currentLevelId: targetNodeId,
    breadcrumbs: [...state.breadcrumbs, { id: node.id, name: node.name }],
    currentNodes: childNodes,
    levelHistory: [...state.levelHistory, historyEntry],
  });
}
```

## 四、开发规范

### 4.1 前端开发规范

**组件开发**：
- 使用函数式组件 + Hooks
- 组件命名使用 PascalCase
- 文件命名使用 PascalCase
- 使用 TypeScript 接口定义 props

**状态管理**：
- 全局状态使用 Zustand
- 组件内部状态使用 useState
- 计算属性使用 useMemo
- 回调函数使用 useCallback

**代码风格**：
- 使用 TypeScript 严格模式
- 使用 `const` 而非 `var`
- 避免未使用的变量和导入
- 使用 `===` 而非 `==`

### 4.2 后端开发规范

**API设计**：
- RESTful 风格
- 使用统一的响应格式 `{ code, msg, data }`
- 使用 HTTP 状态码
- 参数校验使用 Pydantic

**数据库操作**：
- Repository 层封装数据库操作
- 使用参数化查询防止注入
- 事务操作使用 `session.run`

**代码风格**：
- 使用 Python 3.12+ 语法
- 使用类型提示
- 使用 `async/await` 异步编程
- 函数命名使用 snake_case

## 五、开发流程


## 六、故障排查

### 6.1 前端常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 页面白屏 | Vite 模块解析错误 | 检查 importmap 配置 |
| 节点不显示 | X6 容器尺寸为0 | 确保容器有明确的宽高 |
| 拖拽无效 | 事件被拦截 | 检查 event.stopPropagation |
| 连线消失 | 节点 ID 不匹配 | 检查数据源和节点 ID |

### 6.2 后端常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| PostgreSQL 连接失败 | 数据库未启动 / `DATABASE_URL` 错误 | 启动容器并检查连接串（容器内主机名 `postgres`） |
| API 500 错误 | 未捕获异常 | 查看后端日志 |
| 数据表不存在 | 空库未执行迁移 | `cd backend && .venv/bin/python -m alembic upgrade head` |
| 接口 404 | 路径缺少 `/api/v1` 前缀 | 按 [15_API接口列表.md](./15_API接口列表.md) 调用 |

## 七、性能优化

### 7.1 前端优化

| 优化点 | 实现方式 |
|--------|----------|
| 节点渲染 | 使用 X6 batchUpdate 批量更新 |
| 列表渲染 | 使用 React.memo 缓存组件 |
| 状态更新 | 使用 useCallback 避免不必要重渲染 |
| 图片优化 | 使用合适的尺寸和格式 |

### 7.2 后端优化

| 优化点 | 实现方式 |
|--------|----------|
| 查询优化 | 按 `docs/19_数据库设计.md` 建立 PostgreSQL 索引（`ix_nodes_map`、`ix_props_map_node` 等） |
| 连接池 | 复用 asyncpg 连接池（`DB_POOL_SIZE` / `DB_MAX_OVERFLOW`） |
| 批量读取 | 整树接口一次查询 `maps/nodes/props`，服务层内存组装，避免 N+1 |
| 缓存 | 可选 Redis 缓存热点数据（当前版本未引入） |

## 八、扩展指南

### 8.1 添加新功能

1. 在 `types/index.ts` 中定义新类型
2. 在 `store/index.ts` 中添加状态和操作
3. 创建新组件或修改现有组件
4. 更新 `GraphCanvas.tsx` 集成新功能

### 8.2 添加新 API

1. 在 `backend/app/api/v1/<模块>/` 中新增路由、schema 与 service
2. 业务逻辑放入对应 `service.py`，数据访问使用 SQLAlchemy ORM（参数化）
3. 如涉及表结构变更，修改 ORM 模型并生成 Alembic 迁移（`alembic revision --autogenerate`）
4. 在 `app/api/v1/router.py` 中注册路由
